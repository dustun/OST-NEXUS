# Контекст Catalog

Catalog — первый ограниченный контекст OST NEXUS. Он отвечает за редакционные данные музыкального мира и не содержит логику самого проигрывателя.

## Модель данных

~~~text
Game
  └── Track
        ├── Composer (many-to-many)
        ├── Mood (many-to-many)
        ├── SceneType (many-to-many)
        └── PlaybackSource (one-to-many)
~~~

- **Game** — игровая вселенная или отдельная игра;
- **Track** — независимое музыкальное произведение внутри игры;
- **Composer** — автор музыки с ролью в pivot-связи;
- **Mood** — редакционное настроение для радио и фильтрации;
- **SceneType** — тип игровой сцены;
- **PlaybackSource** — конкретный источник воспроизведения у провайдера.

Трек не хранит YouTube ID напрямую. Поэтому позднее к одному треку можно подключить другой официальный источник, не меняя сущность трека, избранное и ссылки.

## Публикация

Игры, треки, композиторы и источники имеют состояния:

1. **draft** — редактируется и не виден публично;
2. **published** — доступен публичному API;
3. **archived** — снят с публикации, но сохранён в базе.

Переходы состояния контролируются доменной моделью. Filament и API не должны менять статус в обход прикладного сценария.

## Первый набор данных

Команда **task db:seed** создаёт идемпотентный демонстрационный каталог:

- 1 опубликованная игра;
- 3 опубликованных трека;
- 1 композитор;
- 2 настроения;
- 2 типа сцен;
- 1 YouTube-источник для каждого трека.

В качестве источника используется официальный демонстрационный ролик YouTube IFrame API. Это технический контент для проверки интеграции; редакционные игровые OST будут добавляться отдельно через Filament.

## Команды

~~~bash
task up
task migrate
task db:seed
task backend:test
~~~

Миграция остаётся неизменяемой историей базы и использует строковые значения по умолчанию. Актуальные бизнес-ограничения представлены enum и value objects в **Domain/Catalog**.
